# Безопасность

Сайт работает с данными несовершеннолетних, поэтому приватность здесь — часть
корректности, а не «дополнительное требование».

## Секреты

- Только окружение: `.dev.vars` локально, `wrangler secret put` на проде.
  Никогда — в исходники, в клиентский бандл, в логи, в чат.
- Публичные значения (`TURNSTILE_SITEKEY`, `APP_ORIGIN`) — можно в `[vars]`,
  серверные (`TURNSTILE_SECRET`, `SETUP_TOKEN`, `NOTION_TOKEN`) — только секретом.
- Клиент общается лишь с `/api/*` своего origin; сессия — HttpOnly cookie.

## Мутации и права

- `POST/PUT/PATCH/DELETE` проходят через `assertMutationAllowed(request, env)`
  из `worker/lib/http.ts`: он сверяет `Origin` с `APP_ORIGIN` и требует заголовок
  `x-csrf: 1`, который ставит клиент в `src/lib/api.ts`. Новая мутирующая ручка без
  этой проверки — дырка CSRF. Сейчас её вызывают `worker/api/auth.ts` (setup, login,
  logout, смена пароля) и `handleAdmin` для всех не-GET запросов.
- Права проверяются на сервере (`worker/api/admin.ts`), роль из сессии, а не из тела
  запроса. Скрытая кнопка в интерфейсе — не защита.
- Форма обратной связи: honeypot, ограничение частоты, согласие на обработку данных.

## Данные

- Публичное API перечисляет поля явно. Полная дата рождения, телефон, адрес,
  приказы, медицинские сведения — не отдаются никогда, даже если колонка есть.
- Выборки по спортсмену/обращению — по серверному идентификатору из сессии,
  а не по значению из запроса.
- SQL только через `.bind()`. Строковая склейка допустима лишь в генераторах
  сид-скриптов, где данные ваши и проверены.

## Загрузки и файлы

- Проверка сигнатуры файла, а не расширения; лимиты 8 МБ для картинок, 20 МБ для PDF.
- Имя файла генерируется заново, путь вида `images/<uuid>.png`; выдача — через
  контролируемый маршрут, а не публичный листинг R2.

## Перед публикацией

Проверить: `/api/*` без секретов в ответах, чужой Origin → 403, выход из аккаунта
чистит сессию, `robots.txt` закрывает `/admin` и `/api`, демо-данные не индексируются.
