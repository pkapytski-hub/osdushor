# Отладка по шагам

Не начинайте с правки. Сначала зафиксируйте, что именно не так.

1. **Воспроизвести.** Команда или URL, на котором видно проблему, и что видно вместо
   ожидаемого. Если воспроизвести не удаётся — это первая задача, а не повод править код.
2. **Сузить.** Локально или на проде? Только одна страница или все? Данные или рендер?
   Проверяйте по одному слою: ответ API (`curl`), затем страница, затем логи воркера.
3. **Гипотеза.** Одна, проверяемая: «API отдаёт пустой `results`, потому что джойн
   идёт по `r.competition_id`, а он NULL». Не «что-то с запросом».
4. **Минимальный эксперимент.** SQL-запрос, один `curl`, один `node -e`. Никаких
   «поправлю сразу пять мест и посмотрю».
5. **Фикс.** Наименьшее изменение, которое закрывает причину, а не симптом.
6. **Повторная проверка.** Тот же воспроизводящий шаг из п. 1. Затем `npm run typecheck`,
   а для UI — реальная страница, а не только сборка.

## Привычки, которые экономят время

- Читать сообщение об ошибке целиком, включая путь и номер строки.
- Проверять предположения о данных: `SELECT COUNT(*)`, `typeof`, реальный JSON ответа.
- Не менять окружение, чтобы «заработало»: если сломалось в workerd, а в Node работает —
  ищите несовместимость, а не обходите её.
- После фикса удалить временные логи и файлы, которые создали для диагностики.
