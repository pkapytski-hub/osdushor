# Workers в проекте ОСДЮШОР

Точка входа — `worker/index.ts`, `export default { fetch }`. Ниже — то, на чём чаще
всего ломается: код работает локально в Node-скрипте, но не в воркере.

## Runtime

- V8-изолят, а не Node: нет `fs`, `path`, `process`, `Buffer` по умолчанию,
  нет долгоживущего состояния между запросами (глобальные переменные живут только
  в пределах изолята и могут исчезнуть).
- `nodejs_compat` в `wrangler.toml` **не включён** (`compatibility_flags` отсутствует).
  Если понадобился `node:*` или `Buffer` — сначала добавить флаг и прогнать
  `npm run build:worker`, а не тащить зависимость в воркер.
- Тяжёлая работа (разбор xlsx, импорт из Notion, оптимизация картинок) живёт в
  `scripts/` под Node. Воркер только читает готовые данные из D1/R2.

## Биндинги

- `env.DB` — D1, `env.FILES` — R2, `env.ASSETS` — статика из `dist/`.
  Типы в `worker/env.d.ts`; новый биндинг = правка и `wrangler.toml`, и типа.
- Переменные: `APP_ORIGIN`, `ENVIRONMENT`, `DEMO_DATA`, `SETUP_TOKEN`,
  `NOTION_TOKEN`, `TURNSTILE_SITEKEY`. Публичные — `[vars]`, секреты — `wrangler secret`.
- `run_worker_first = true` и `not_found_handling = "single-page-application"`:
  воркер обрабатывает запрос раньше ассетов и сам вставляет мета-теги в HTML.
  Ошибка API не должна отдавать HTML-фолбэк: `/api/*` всегда JSON.

## D1

- Только связанные параметры: `.bind(a, b, c)`. Склейка SQL строками — прямой путь
  к инъекции; в проекте это запрещено везде, кроме генераторов сид-скриптов.
- Ограничение — около 100 связанных параметров на запрос и 1000 строк на ответ:
  списки фильтровать на сервере, а не тянуть всё и резать в браузере.
- Несколько записей — `env.DB.batch([...])`, это атомарно и быстрее цикла.
- `COUNT(*)` и `ORDER BY` без индексов на больших таблицах (`competition_results`
  уже 4000+ строк) — проверять план через `EXPLAIN QUERY PLAN` при новых выборках.

## Локальная отладка

- `npm run dev:api` = Miniflare + локальные D1/R2 в `.wrangler/`. Боевые данные
  туда не попадают, пока не добавить `--remote`.
- Логи: `wrangler tail osdushor` для прода, консоль процесса — локально.
- Быстрая проверка запроса: `curl -s http://127.0.0.1:8787/api/... | head -c 500`.
- Лимиты CPU и памяти лучше ловить заранее: циклы по всем результатам в воркере —
  плохая идея, агрегация должна быть в SQL.
