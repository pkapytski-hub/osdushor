# Официальный сайт Гродненской ОСДЮШОР им. Ю. К. Культиясова

Публичный сайт школы настольного тенниса и защищённая панель управления контентом.
Публичная часть отдаётся статикой (React + Vite), API и SEO-разметка собираются
Cloudflare Worker'ом, данные хранятся в D1 (SQLite), файлы — в R2.

## Стек

| Слой | Технологии |
| --- | --- |
| Фронтенд | React 19, TypeScript, Vite 8, Tailwind CSS 4, React Router 7 |
| API и SSR-мета | Cloudflare Worker (ES-модуль), D1, R2 |
| Шрифты и изображения | локальные woff2, WebP/JPEG-наборы с `srcset` |
| Проверки | `tsc --noEmit` для фронтенда и воркера, сборка Vite и esbuild |

Ключи и пароли не попадают в клиентский код: браузер общается только с `/api/*`
своего же домена, сессия хранится в HttpOnly-cookie.

## Требования

- Node.js 22.12+ (22.x)
- Аккаунт Cloudflare (для публикации), Wrangler CLI в зависимостях проекта
- Для локальной работы — `wrangler dev` (Miniflare), отдельный аккаунт не нужен

## Локальный запуск

```sh
# 1. Зависимости и локальные переменные.
npm ci
cp .dev.vars.example .dev.vars
node -e "console.log(require('node:crypto').randomBytes(24).toString('hex'))"   # код → SETUP_TOKEN

# 2. Схема D1 в локальной базе. Нужна один раз: без неё API отвечает ошибками.
npm run db:init

# 3. Сборка статики. wrangler.toml отдаёт ассеты из ./dist, поэтому без этого шага
#    `npm run dev:api` падает с `assets.directory ... does not exist`.
npm run build:frontend
```

Дальше нужны два процесса в двух отдельных терминалах: Worker и Vite не заменяют
друг друга, и `npm run dev` сам по себе поднимает только фронтенд.

```sh
# терминал 1 — Worker, API и локальные D1/R2 на http://127.0.0.1:8787
npm run dev:api

# терминал 2 — Vite на http://127.0.0.1:5173, проксирует /api на 8787
npm run dev
```

Откройте `http://127.0.0.1:5173`. Админ-панель — `/admin`. Если `npm run dev`
запущен без `npm run dev:api`, страницы открываются, но запросы к `/api`
возвращают `502` от прокси: данные, формы и админка в этом режиме не работают.

Полностью собранную версию (статика + Worker) можно проверить одной командой:

```sh
npm run build && npm run dev:api         # http://127.0.0.1:8787
```

`npm run preview` поднимает только статику Vite без API — формы и админка там работать не будут.

### Первичная настройка администратора

1. В `.dev.vars` задайте случайный `SETUP_TOKEN` (не короче 16 символов).
   Пустым его оставлять нельзя: страница `/admin/setup` откроется, но сервер вернёт
   `503 setup_unavailable`, а `/api/auth/me` будет отдавать `setup_available: false`.
   Заглушка `change-me-local-setup-token` из `.dev.vars.example` — тоже не значение:
   замените её, иначе код настройки знает каждый, кто видел шаблон.
2. Откройте `/admin/setup`, введите код из `SETUP_TOKEN`, служебный e-mail, имя и пароль
   (не короче 12 символов).
3. Настройка работает только пока в таблице `staff` нет ни одной записи. Повторный вызов
   вернёт `409`. Дальше вход выполняется на `/admin/login`.

Пароли хранятся как PBKDF2-хеш с индивидуальной солью, сессии — в таблице `sessions`
по хешу токена, с ограничением по времени жизни и признаком активности сотрудника.

## Работа с разных устройств

Данные сайта живут в Cloudflare (D1 и R2), поэтому все устройства видят одну и ту же
базу. Локальный клон нужен только для разработки — наполнять базу заново не надо.

| Задача | Устройство | Что нужно |
| --- | --- | --- |
| Новости, календарь, документы, обращения, рейтинг | любое с браузером | войти на `/admin` рабочего сайта |
| Править код | домашний ПК | Node 22.12+, `npm ci`, `.dev.vars` |
| Править код без установки | планшет или телефон | GitHub → Code → Codespaces |

### Домашний ПК

```sh
git clone https://github.com/pkapytski-hub/osdushor.git
cd osdushor
npm ci
cp .dev.vars.example .dev.vars       # NOTION_TOKEN — только если нужен импорт из Notion
npm run db:init && npm run build:frontend
```

Дальше — два терминала, как в разделе «Локальный запуск».

### Планшет и телефон

Репозиторий содержит `.devcontainer/devcontainer.json`: Codespaces сам поднимает среду
с Node 22, ставит зависимости и пробрасывает порты 5173 и 8787. Работает в браузере
на iPad, Android-планшете и телефоне — устанавливать ничего не нужно.

1. Откройте репозиторий на github.com → **Code** → вкладка **Codespaces** →
   **Create codespace on master**. Первый запуск занимает несколько минут.
2. Токен Notion в облачной среде держите секретом, а не файлом: GitHub → Settings →
   Codespaces → **New secret** с именем `NOTION_TOKEN`. Скрипт импорта берёт его из
   переменной окружения, поэтому `.dev.vars` для этого не нужен.
3. Локальная база в облачной среде пустая, схему нужно создать один раз:

   ```sh
   npm run db:init
   npm run db:athletes      # список спортсменов с рейтингами из worker/seed
   ```

4. Запуск такой же, но Vite должен слушать все интерфейсы, иначе проброс порта его
   не увидит:

   ```sh
   npm run dev:api                     # терминал 1: API и локальные D1/R2 на 8787
   npm run dev -- --host 0.0.0.0       # терминал 2: превью 5173 откроется само
   ```

5. Публикация из облака — та же команда: `npm run deploy` (один раз понадобится
   `npx wrangler login`, ссылка откроется в браузере устройства).

Правки переносятся через git: коммит и push из Codespaces, на ПК — `git pull`.
Книгу учащихся в облако не загружайте без необходимости: в ней персональные данные,
и в репозиторий она не попадает (`.gitignore`). Данные в облачной среде локальные и с
рабочей базой не пересекаются.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `APP_ORIGIN` | Публичный origin сайта. Используется для canonical, Open Graph, sitemap, проверки Origin/CSRF и ссылок в письмах-подтверждениях. На проде — `https://ваш-домен.by` без слэша. |
| `ENVIRONMENT` | `development` или `production`. В production демо-предупреждения скрываются. |
| `DEMO_DATA` | `true` — наполняет базу демонстрационными новостями, соревнованиями и фото. На проде выключите и удалите демо-записи кнопкой на дашборде. |
| `SETUP_TOKEN` | Одноразовый код создания первого администратора. После настройки можно удалить. |
| `NOTION_TOKEN` | Токен интеграции Notion для `npm run results:import`. В облачной среде задаётся секретом Codespaces. |

Локально значения лежат в `.dev.vars` (в git не попадает). На Cloudflare — через
`wrangler secret put` или переменные окружения Worker'а.

## Контент и демо-данные

- Все тексты, контакты, реквизиты и условия набора редактируются в `/admin/settings`.
  Незаполненные поля выводятся как «Уточняется», а на дашборде показывается список
  того, что обязательно заполнить до официального запуска.
- Демо-записи помечены бейджем «Демо» и исключаются из индексации (`noindex`).
  При `DEMO_DATA=false` публичное API их не отдаёт. Удалить их полностью можно
  кнопкой «Удалить демо-данные» на дашборде.
- Загружаемые файлы проверяются по сигнатуре: JPG, PNG, WebP, AVIF до 8 МБ,
  PDF до 20 МБ. Имя файла генерируется заново, путь вида `images/<uuid>.png`.
- Форма обратной связи защищена honeypot-полем, ограничением частоты отправок и
  проверкой Origin. Обращения видны только сотрудникам в `/admin/messages`.

## Турниры и рейтинг

Субботние турниры школы проводятся прямо в панели: `/admin/tournaments`.

1. **Спортсмены** — `/admin/athletes`: список воспитанников с текущим рейтингом.
   Новому спортсмену задайте стартовый рейтинг (например, 100). Рейтинг меняется
   только при подведении итогов турнира; вручную его можно поправить в карточке.
2. **Турнир** — `/admin/tournaments/new`: название, дата, формат
   («круговой» или «группы + плей-офф»), размер группы, число участников плей-офф
   и коэффициент (стандарт школы — 0,5). Публикация включает турнир на сайте.
3. **Состав** — отметьте участников из списка спортсменов и сохраните состав.
   Порядок номеров определяется текущим рейтингом.
4. **Лиги и жеребьёвка** — лига определяется местом в общем рейтинге школы: 1 лига —
   места 1–50, 2 лига — 51–70, 3 лига — с 71-го и ниже. Место считается среди всех
   активных спортсменов, а не только пришедших на турнир, поэтому лига не меняется от
   того, кто именно пришёл в субботу. Лига влияет только на время: 1 лига обычно играет
   в 9:00, 2 и 3 — в 12:00 (расписание показывается на странице турнира). На жеребьёвку
   лига не влияет: участники сортируются по рейтингу и делятся на группы подряд —
   12 человек при группе по 6 дают группы 1–6 и 7–12. «Змейки» нет, лиги не разделяются,
   поэтому в одной группе могут играть спортсмены разных лиг.
5. **Результаты** — счёт по сетам (например, 3:1). Таблицы групп и места
   пересчитываются сразу; после заполнения всех групп доступна кнопка
   «Сформировать плей-офф» — одна общая сетка из сильнейших по итогам групп,
   следующие круги создаются автоматически.
6. **Итоги** — «Подвести итоги» фиксирует общие места турнира, записывает
   изменение рейтинга в историю и обновляет рейтинг спортсменов. Победитель турнира —
   первое место. Ошибку можно откатить кнопкой «Отменить итоги»: рейтинги вернутся
   к значениям до турнира.

Формула повторяет рабочую книгу школы. Разница всегда считается как «рейтинг
победителя − рейтинг проигравшего» и берётся из рейтингов на начало турнира
(результаты встреч не пересчитывают рейтинг по ходу):

- победа: `(100 − разница) / 10 × коэффициент`;
- поражение: `(100 − разница) / 20 × коэффициент`;
- если разница 100 и больше, встреча рейтинг не меняет — но победа более слабого
  над сильным (отрицательная разница) даёт обоим больше очков, чем при равных рейтингах;
- изменения по всем встречам суммируются и округляются до 0,1; итоговый рейтинг —
  рейтинг на начало турнира плюс эта сумма.

Публичные страницы: `/turniry` — турниры с архивом по годам, `/turniry/<id>` —
таблицы, встречи, сетка и итоговые изменения рейтинга, `/reyting` — текущий
рейтинг с поиском, фильтром по году рождения и лигой каждого спортсмена.

### Настоящий список спортсменов

Список воспитанников с рейтингами из рабочей книги школы лежит в
`worker/seed/athletes.json` (96 человек, выгрузка из «РЕЙТИНГ.xlsx» от 30.10.2026).
Записать его в базу:

```sh
npm run db:athletes            # локальная D1
npm run db:athletes:remote     # рабочая D1
```

Скрипт сопоставляет записи по фамилии и году рождения, поэтому его можно запускать
повторно — дублей не будет. Уже существующим спортсменам рейтинг не перезаписывается
(он мог измениться после турниров); принудительно — флагом `--force-ratings`.
Демо-заглушки «Спортсмен NN» удаляются флагом `--prune-demo` (только осознанно:
вместе с ними уходят турниры, где играли одни заглушки).

## Роли

| Роль | Возможности |
| --- | --- |
| `admin` | весь контент, настройки сайта, SEO, доступы, журнал действий, демо-данные, экспорт |
| `editor` | публикации, соревнования, достижения, тренеры, галерея, документы, расписание, обращения |

Ограничения проверяются на сервере (`worker/api/admin.ts`), а не только в интерфейсе.
Администратор не может отключить сам себя или снять с себя роль администратора;
нельзя удалить последнего активного администратора.

## SEO

- Уникальные `title`, `description`, canonical и Open Graph для каждой страницы.
- Worker подставляет мета-теги и JSON-LD в HTML до отдачи — контент виден поисковикам
  и социальным сетям без выполнения JavaScript.
- `/sitemap.xml` и `/robots.txt` генерируются Worker'ом из опубликованных записей;
  `/admin` и `/api` закрыты в robots.
- Демо-материалы и служебные страницы закрыты `noindex`.
- Структурированные данные: `SportsOrganization`, `NewsArticle`, `SportsEvent`,
  `BreadcrumbList`.

## Публикация

Полный пошаговый чек-лист — в [DEPLOY.md](DEPLOY.md): ресурсы D1/R2, переменные
и секреты, домен, проверки после деплоя и типовые проблемы.

```sh
# 1. Ресурсы Cloudflare
wrangler d1 create osdushor-db          # id базы → database_id в wrangler.toml
wrangler r2 bucket create osdushor-files

# 2. Схема и секреты
npm run db:init:remote
wrangler secret put SETUP_TOKEN
# APP_ORIGIN и ENVIRONMENT задайте в wrangler.toml [vars] или как секреты

# 3. Сборка и деплой
npm run deploy
```

После деплоя:

1. Откройте `https://домен/admin/setup`, создайте администратора, затем удалите
   секрет `SETUP_TOKEN`.
2. Выставьте `DEMO_DATA=false`, удалите демо-записи на дашборде.
3. Заполните обязательные поля в настройках (адреса, телефоны, условия набора,
   реквизиты, режим работы) — дашборд подскажет, что осталось.
4. Проверьте `/robots.txt`, `/sitemap.xml`, отправку формы обратной связи и вход в панель.

Для собственного домена добавьте `routes`/`custom_domain` в `wrangler.toml` и
не забудьте, что `APP_ORIGIN` должен совпадать с публичным адресом — иначе canonical
и проверка Origin будут указывать на неверный домен.

## Персональные данные

Сайт предназначен для работы с данными несовершеннолетних, поэтому:

- в открытом доступе нет телефонов детей, медицинских сведений и документов с
  персональными данными;
- фотографии воспитанников публикуются только при наличии согласий законных
  представителей — об этом есть уведомление в подвале и в политике;
- форма обратной связи требует явного согласия на обработку данных, а текст
  политики доступен по ссылке `/politika-personalnyh-dannyh`;
- обращения хранятся в закрытом разделе и доступны только сотрудникам;
- аналитика подключается только после согласия посетителя (см. `src/components/Analytics.tsx`).
